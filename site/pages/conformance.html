Conformance

A Unix tool is only useful if it does what you expect. When you type sort -n or sed s/a/b/, you want the answer you would get on any other Unix. So the tools in maux are tested against real ones.

At a glance

{{gen:conformance_summary}}

How closely

The headline: most of the command set follows POSIX, and is tested that way. Some of it is older on purpose. The shell is the Version 7 Bourne shell with the POSIX parts that fit. ed is a small version of the original editor. vi and ex come from Berkeley, and have been brought up to the POSIX text. The table says which is which.

How it is checked: most tests run a command on maux and run the same command on a Mac, then compare the output and the exit status byte for byte. Where the Mac’s tool and the POSIX text disagree, the POSIX text wins. The Mac’s own tools are BSD tools, and its vi and ex are Vim. The counts below come from test runs on {{fact:cf_date}}. maux runs on an emulated enhanced IIe for those runs, not on a real machine: they establish what the software does, not how the original hardware behaves.

How to read the counts

A test is one command, run on maux and run again on the reference. It counts only if maux gave the same answer, byte for byte, including the exit status. Something maux does not do, such as grep -E, is a difference, not a match, and is listed by name under “Where it differs”. {{fact:cf_util_pass}} of the {{fact:cf_util_total}} tests on the standard utilities gave the same answer, and {{fact:cf_util_gaps}} are known differences. (The test run itself prints {{fact:cf_util_gate}} of {{fact:cf_util_total}}, because it also counts a known difference as a pass for as long as it stays different. That is a check on the list of differences, not a match.)

Not every test has a running reference to compare with. Of the {{fact:cf_util_pass}} that agreed, {{fact:cf_util_host}} compare maux with the Mac’s own tool. The other {{fact:cf_util_hand}} check maux against an expected answer written by hand, where the Mac has no tool to compare with (cal, for one) or its tool disagrees with the POSIX text. Those are assertions, not comparisons. The shell, sed, vi, ex and regular-expression counts are separate runs against their own references, named in the table.
