L3. Your own filter

Learn / L3

Goal: a program of about forty lines that composes with every other program on the machine.

What you need

L2: you can assemble, link and run a program. This lesson builds by hand with nas and ld; L5 hands that to make.

The file

The program reads one byte at a time with GETC until end of file, raises it if it is a letter from a to z, and writes it with PUTC.

{{file:examples/upcase/upcase.s}}

The session

The program is run three ways: with its input redirected from a file (<), as the last stage of a pipe, and in the middle of one.

{{gen:session}}

What just happened

A maux program has three files open when it starts: standard input (0), standard output (1) and standard error (2), the constants FD_STDIN, FD_STDOUT and FD_STDERR from /usr/inc/sc.fd.equ. GETC takes the file number in X; the byte comes back in A with the carry clear, and a set carry means end of file. The shell connects those three files before the program starts, so upcase neither knows nor cares whether its input is a file, a keyboard or another program.

The one subtle line is the test for a letter. maux writes text with the high bit set and ends lines with $8D; a file that came from another Apple II program has the high bit clear and ends lines with $0D. The program tests only the low seven bits and passes every other byte through untouched, so it gives back the convention it was given. That is the rule for every maux filter. The session's second line is #!/BIN/SH because it is the shell script from L1, raised.

You may notice the pipelines stop at three programs. A pipeline of four, such as ls /bin | ./upcase | sort | head -3, prints sh: syntax error: the shell holds at most three stages. Three is enough for this lesson.

Try next

Make a second filter, downcase, by changing the range test and the bit you clear. Which instruction changes? Which one sets a bit instead?
