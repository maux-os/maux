L6. hello, world, in PLASMA

Learn / L6

Goal: compile a program in PLASMA, a small language that compiles to bytecode, with the compiler running on the machine itself, run it, and then run the same program again as a single file cut by the plasma cutter.

What you need

L1 (you can edit a file with vi) and L5 (you can write a Makefile). The files are on the disk in /usr/src/examples/HELLOPLA; this lesson types them, because typing a program is how you learn it.

Where the program comes from

The program is not ours. It is src/samplesrc/hello.pla from PLASMA, written by David Schmenk (github.com/dschmenk/PLASMA, MIT licence, Copyright © 2010-2022 David Schmenk), and it is here byte for byte, with his indentation and his line continuations. A check compares our copy with his file at the PLASMA version maux builds against, and fails the build if a byte differs. The licence text is in man licenses.

The files

Six lines. include pulls in the declarations of the runtime, puts prints a string, and a backslash at the end of a line continues the statement on the next one. done ends the module.

{{file:examples/hellopla/hello.pla}}

The Makefile is maux's own. PLASMA's compiler exits with success even when it reports an error, and make runs each line without a shell, so the rule removes the old module first and lists the new one afterwards: ls fails if the module is not there, and that stops make. Each indented line starts with a TAB.

{{file:examples/hellopla/Makefile}}

The session

Typed in vi, a key at a time, then built and run. Near the end it runs HELLO, the cooked copy of the same program that came on the disk, from /usr/src/examples/HELLOPLA.

{{gen:session}}

What just happened

plasm compiled hello.pla into hello.mod, a relocatable module (type $FE). It reported 23 bytes: a program of this kind is tiny, and so is the compiler's room. plasm fits programs of a few hundred bytes of code and data, enough for hello, world and a sieve, and the manual page says where the limit is. plasma hello.mod then ran it: plasma starts the PLASMA virtual machine, loads the runtime, reads the module, resolves the names it imports and runs it. All of that happens again on every launch.

The plasma cutter

/usr/src/examples/HELLOPLA/HELLO is the same program with the loading already done. It was made on the host, not on the machine, by plascut, the plasma cutter: it does what plasma does at launch (read the runtime and the module, relocate, bind every import) once, and writes the result as one flat BIN file that the shell starts like any command. Nothing is left to resolve when it runs. The module it cuts is the one plasm writes (the host compiler is run without its optimizer, as plasm has none), and the file on the disk is checked against a fresh cut of David Schmenk's hello.pla, so it cannot drift from the source.

{{gen:hellopla_figures}}

The saving is the loading, so it grows with how much a program has to load: small for this one, larger for nas, which is shipped cut and which make starts again for every file. In the gate that checks the cutter, one warm nas run on a small fixture (it assembles to {{fact:plascut_fixture_bytes}} bytes) takes {{fact:plascut_cooked_mcycles}} million cycles cut against {{fact:plascut_modular_mcycles}} million loaded through plasma NAS: {{fact:plascut_saved_mcycles}} million cycles, {{fact:plascut_saved_percent}} percent less, at revision {{fact:plascut_rev}}. nas, plasm and this HELLO are all cut programs.

Try next

Change the message and run make again. Does it rebuild? It compares the modification times ProDOS keeps, and the one-minute rule from L5 applies, so a change made within a minute of the last build can be skipped; touch hello.pla is the way out. Then break the source on purpose and see what plasm prints and what the Makefile does about it. Finally compare ls -l of HELLO and hello.mod: what type is each?
