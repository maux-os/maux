A floppy, through dd, into a ShrinkIt archive

A 5.25-inch ProDOS floppy sits in drive 1, an image of a disk that shipped on the GEM CD in 1990. dd reads it as 280 blocks and pipes the bytes straight into nulib2, which writes them as a ShrinkIt disk archive, a .SDK. The demo lists the archive, writes the disk back out of it, mounts that file and lists the volume, then compares it with the disk inside the 1990 archive it came from. cmp prints nothing.

The gate that proves it

This film is made by site/demos/ddshrink.py. Run as assertions, the same file is {{gen:demogate}}, and it runs with the rest of the tests. The floppy is the disk inside DEMOPROG.SDK, a 1990 ShrinkIt archive from the GEM CD, extracted on the host by an independent NuFX reader. The gate requires that dd reports 280 blocks in and 280 out; that nulib2 -v shows exactly one Disk record of 143,360 bytes; that the mounted image appears under its volume name and ls shows exactly the 14 files the host finds on the disk; that the 1990 archive lists as one Disk record of the same size; that the volume is unmounted again afterwards; that cmp of the two extracted disks is silent; and that cksum of both equals the host’s checksum of the disk. Everything is made in /tmp. The checks themselves were tested: with nulib2 replaced by a copy of cat, or dd replaced by true, the dd rows fail; with mount replaced by true the first mount listing fails; with umount replaced by true the listing after it fails; with one byte of the floppy flipped the gate fails before anything runs, because the file in the drive is not the archive’s disk; with a cmp that prints a difference, the silence row fails; with cksum replaced by true, the checksum row fails.
