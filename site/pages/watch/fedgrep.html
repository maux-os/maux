grep, written with ed

grep is named after an ed command, g/re/p: global, regular expression, print. The demo types it again into vi as a six-line shell script that hands a here-document to ed, and runs it on the Federalist Papers: all 85 are on the disk, one file each, as plain public-domain text. It runs the script on Madison's No. 10, the paper on faction, runs the real grep on the same paper, and lets cmp say nothing. Then it runs the script over the 26 papers this edition heads MADISON, with xargs, sped up (the badge under the screen says by how much), and checks the bytes.

Why the 26 papers this edition heads MADISON, and not all 85

ed keeps the whole file in memory and sizes that memory when it starts. At the revision this was filmed on (63fb62c2), 462 lines of No. 83 (28,613 bytes) load and 463 lines (28,682 bytes) are refused. No. 83, the longest paper, is 34,200 bytes, so ed answers its r command with ? and the script prints that question mark, where the real grep prints nothing. The film does not hide it; it picks the papers this edition heads MADISON, none of which is near the limit. The headings are the edition's, not the authors': who wrote the disputed papers is a question this film does not settle.

The gate that proves it

This film is made by site/demos/fedgrep.py. Run as assertions, the same file is {{gen:demogate}}, and it runs with the rest of the tests. It requires that the script reads back from vi as typed, that wc counts the papers on the disk, that head shows No. 10 as headed MADISON, dated 22 November 1787, that grep.sh prints exactly the lines of No. 10 that hold the word, in order, as the host finds them in the same bytes, that the real grep prints the same lines, and that cmp on the two captures prints nothing. For the papers headed MADISON it requires that the guest finds 26 of them; that cksum of the list, of the grep.sh output and of the grep output equals the host's checksum of the bytes each must hold; that cmp says the grep.sh output and the list differ (a positive control, so a cmp that always says nothing cannot pass); and that cmp on the two outputs prints nothing. The checks themselves were tested: with ed, grep, cmp, xargs, head or wc replaced by a copy of cat, with cmp, xargs, cksum or vi replaced by true, the demo fails at the row that uses it.
