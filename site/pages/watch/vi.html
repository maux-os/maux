vi hands its text to other programs

Watch / vi

{{gen:player}}

A real vi, at 80 columns, on a new file in /tmp. Its ! commands pass text to the rest of the system: :r !ls /usr/man | head -8 reads a pipeline's output into the buffer, :%!sort -r hands the whole buffer to sort and takes the answer back, :2,4!tr A-Z a-z sends only lines 2 to 4 through tr, and :%!nl numbers every line. Then the file is written, :!wc -l notes runs wc on it through a shell escape, and cat shows what is on the disk.

The gate that proves it

This film is made by site/demos/vi.py. Run as assertions, the same file is {{gen:demogate}}, and it runs with the rest of the tests. After every editing step it reads the 23 rows of the editing window and requires the buffer's lines, in order, with a ~ on every row below them; the bottom status row is not read. Every cell must match exactly except one: the cell under the cursor, which the Apple paints as a different glyph for a lower-case letter, and the gate accepts only that glyph, at the cursor's position. The expected rows are computed on the host from the bytes of the image (the names in /usr/man) and what sort, tr and nl do to them; nothing about a result is typed into the demo. It requires that the held output of :!wc -l notes says 8 lines for the file just written, that cat on the file shows the numbered list in order, that cksum equals the host's checksum of the bytes the file must hold, and that no editor temporary file is left in the directory. The checks themselves were tested: with sort or tr replaced by a script that changes one letter of one line, with sort, tr, head or wc replaced by a copy of cat, and with nl, wc, ls or sh replaced by true, the demo fails at the row that uses it.

What this vi does not do yet

The filter commands are the colon forms, which vi hands to its ex engine. The classic normal-mode forms !! and !} are not implemented: ! in command mode is ignored (listed under BUGS in vi(1)), so the film uses the colon forms only. Also, :w !cmd, which pipes the buffer out to a command, does not yet hold the command's output on the screen as POSIX vi does, so the film does not show it.
