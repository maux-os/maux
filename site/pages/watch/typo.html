A build error, read and fixed the old way. The film copies the hello example, changes one letter in vi (jsr PUTS becomes jsr PUTZ), and runs make, which fails. nas has said what is wrong, on make's screen, but it scrolls away. Run alone, with its complaints sent to a file, it keeps them: nas hello.s 2> ERRS, and cat ERRS reads them again, the label, the file and the line. vi goes straight to that line, the letter is put back, and make builds a program that says hello, world.

What nas says, and where

An unknown label is reported as nas: unknown label PUTZ (hello.s line 35), followed by nas: pass 2 failed. Both lines go to standard error, file descriptor 2, so 2> catches them and the screen stays quiet; the success line, nas: 32 bytes -> hello.o, goes to standard output. The line number counts from 1 in the file named in the parentheses, which is what vi counts, so :35 lands on the mistake. (vi +35 is not accepted here, so the film types the colon form.)

Why there is no make clean

The film runs with the clock card off, so every file has one date, and with a clock card ProDOS would date files only to the minute. Either way make can miss an edit that came soon after a build. It does not matter here: this failure (an unknown label, found in the second pass, before the object file is opened) leaves no hello.o, which the film shows with ls, so after the repair make has nothing stale to trust.

The old ways

The captions lean on two Unix facts. The Bourne shell of Version 7 already redirected a file descriptor chosen by a leading digit, as in 2>&1: see the V7 sh(1) page. And the V7 ed(1) page lists its diagnostics: ? for errors in commands, and ?name for an inaccessible file.

The gate that proves it

This film is made by site/demos/typo.py. Run as assertions, the same file is {{gen:demogate}}, and it runs with the rest of the tests, on both displays. The line number comes from the host reading the lesson's hello.s, so the film cannot drift from the lesson. It requires that make prints the nas command, nas's two lines and make's own failure line; that nas hello.s 2> ERRS prints nothing to the screen; that ERRS holds exactly the two lines, with the right file and line; that no hello.o is left; that after the repair cmp against the lesson's file is silent; and that the rebuilt program says hello, world. The checks themselves were tested: with nas replaced by a copy of true, with a line added at the top of the lesson's file, and with the film expecting the wrong line, it fails at the row that checks make's output.
