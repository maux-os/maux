Stop vi, run make, carry on

Watch / stopvi

Job control and virtual consoles, together, on a small project. The film opens hello.s from the hello example in vi and makes an edit it does not save. ^Z stops vi, and make starts in the background. While it builds, chvt 2 moves to a second console, where ps shows vi stopped and make running, each in a bank of its own. Back on console 1, fg returns to vi with the buffer and the cursor where they were, the edit is saved, and make builds the new program.

Why make runs in the background

A make run in the foreground would hold console 1, and chvt is a program: it has to be typed at a shell prompt, and there is no hotkey. So the film starts make as a job, with its output in a file, and the shell gives the prompt back at once. jobs lists vi stopped and make running. The film reads the process numbers off the screen: the one the shell printed when it started make, and the stopped process that ps showed on console 1 before make began. (The film sends ps to a file and filters out the two console shells with grep, because a shell's state at the instant ps looks can be running or waiting, and a recording must say the same on both displays.)

What make saw

make reads the disk, and the edit was still only in vi's buffer, so the first build is the old program and says hello, world. The new one, built after the save, says hello, world, again. Afterwards a plain make prints nothing. The film runs with the clock card switched off, so that every recording is the same, and every file has one date. With a clock card ProDOS would still date files only to the minute, and make treats an equal date as not newer; the edit comes about 50 seconds after the build, so it would be invisible to make either way. The film runs make clean first.

The gate that proves it

This film is made by site/demos/stopvi.py. Run as assertions, the same file is {{gen:demogate}}, and it runs with the rest of the tests, on both displays. It requires that the shell reports vi Stopped and jobs lists it beside the running make; that ps on console 2 holds the process that was stopped, still stopped, and the process the shell numbered for make, in the bank that is its process number, with a child of its own; that console 1, when it is switched back to, is exactly as it was left; that the log make wrote while vi was stopped is the old build and that program says the old greeting; that after fg the same rows are on the screen as before ^Z and a full stop typed there lands right after the edit; that the saved file holds both; that a plain make after the save prints nothing; and that the rebuilt program says the new greeting. No label in the gate holds a process number or any timing. The checks themselves were tested: with make replaced by a copy of true it fails at "jobs lists vi stopped and make running"; with chvt replaced by true it fails at "console 2 is a fresh, blank screen with a prompt".
